## Codebase Patterns
- Use ES6 module imports/exports - all JS files are modules loaded via `<script type="module">`
- Three.js r160 loaded via import maps in index.html, import as `import * as THREE from 'three'`
- Collision system: use registerCollisionBox(id, {x, z, width, depth}) to add objects, checkObjectCollisions() runs automatically in controls.js
- Three.js addons (EffectComposer, passes, etc.) imported from `three/addons/` path
- Constants defined in js/core/constants.js - use these for all magic numbers
- Content data (work history, skills, etc.) lives in js/data/content.js
- HTML validation: all buttons need `type="button"`, headings need content
- Use `let` for module-level exports that need reassignment in init functions
- Shared outlineMaterial in js/core/materials.js - import instead of creating local copies
- Station factory (createStation) handles collision registration and userData - just add meshes to returned group
- Animation pattern: export updateXxxAnimation(deltaTime) from entity file, register in main.js with addUpdateCallback()

## VISUAL DESIGN REQUIREMENTS (CRITICAL - READ BEFORE ANY VISUAL WORK)
- **ALL objects must use voxel/low-poly aesthetic** - Think Crossy Road, Minecraft, or Fez style
- **Use BoxGeometry for EVERYTHING** - No spheres, no cylinders, no smooth shapes
- **Chunky, charming proportions** - Exaggerated features, not realistic
- **Black inverted hull outlines** - Use addOutlineToMesh() pattern from robot.js (BackSide rendering at 1.05-1.06x scale)
- **Bright, saturated colors** - Use toon materials with clear color bands
- **Take screenshots with Playwright MCP** to visually verify EVERY visual change looks good
- Reference: The robot redesign (US-008) is the gold standard - all props/stations should match this quality

## USER FEEDBACK - LAYOUT ISSUES (PRIORITY - FIX BEFORE OTHER FEATURES)
- **CRITICAL: Garage feels like empty room with random objects, NOT like a real garage**
- **Reference: Rick and Morty garage aesthetic** - dense, organized, lived-in feel
- What the reference shows that we're missing:
  - Shelves along walls with items ON them (not just floor props)
  - Pegboard with tools organized in rows
  - Workbench with cabinets/storage underneath (L-shaped)
  - Appliances (washer/dryer) along walls
  - Wall clock, calendar, bulletin board
  - Boxes stacked in corners creating "clutter"
  - Items that belong together are GROUPED together
- **Current problems:**
  - Work stations are too spread apart (each in its own corner)
  - Too much empty floor space
  - Walls are mostly empty (need more wall-mounted items)
  - No sense of "zones" (work area, hobby area, storage area)
- **Fix approach:**
  - Add wall-mounted storage (pegboard, shelves)
  - Add appliances (washer/dryer)
  - Group work stations closer together in back half
  - Create clear zones: work zone (back), hobby zone (right side), entrance (front)
  - Fill corners with stacked boxes and clutter
- See US-073 through US-080 for specific layout improvement stories

## DEBUG TOOLS AVAILABLE
- **Use `http://localhost:8000?dev=true`** - skips loading screen, starts in top-down view
- **Camera views** (keyboard 1-5 or `window.debug.setCamera(mode)`):
  - 1/'follow' = normal gameplay camera
  - 2/'topdown' = bird's eye view of entire floor plan
  - 3/'corner' = high corner view, see everything
  - 4/'front' = see back wall (whiteboard, certs)
  - 5/'side' = see from left side
- **Console API**:
  - `window.debug.getFloorPlan()` - ASCII map of layout
  - `window.debug.listObjects()` - all objects with positions
  - `window.debug.teleport(x, z)` - move robot instantly
  - `window.debug.getSceneInfo()` - full scene summary
  - `window.debug.getRendererStats()` - draw calls, triangles

## Key Technical Notes
- OutlinePass from Three.js r160 had issues - use inverted hull technique instead (BackSide rendering at 1.05-1.06x scale)
- Wall-mounted objects need rotation: left wall = -Math.PI/2, right wall = Math.PI/2
- Wall objects at Z=-19 (wall at Z=-20) need interaction point slightly forward for robot reach
- Canvas Y is inverted from world Z for minimap drawing
- AudioContext must be created on user gesture (click/keypress) per browser policy
- Performance: ~350 draw calls, 8,786 triangles, 120 FPS - excellent headroom
