## Codebase Patterns
- Use ES6 module imports/exports - all JS files are modules loaded via `<script type="module">`
- Three.js r160 loaded via import maps in index.html, import as `import * as THREE from 'three'`
- Collision system: use registerCollisionBox(id, {x, z, width, depth}) to add objects, checkObjectCollisions() runs automatically in controls.js

## VISUAL DESIGN REQUIREMENTS (CRITICAL - READ BEFORE ANY VISUAL WORK)
- **ALL objects must use voxel/low-poly aesthetic** - Think Crossy Road, Minecraft, or Fez style
- **Use BoxGeometry for EVERYTHING** - No spheres, no cylinders, no smooth shapes
- **Chunky, charming proportions** - Exaggerated features, not realistic
- **Black inverted hull outlines** - Use addOutlineToMesh() pattern from robot.js (BackSide rendering at 1.05-1.06x scale)
- **Bright, saturated colors** - Use toon materials with clear color bands
- **Take screenshots with Playwright MCP** to visually verify EVERY visual change looks good
- Reference: The robot redesign (US-008) is the gold standard - all props/stations should match this quality

## USER FEEDBACK - LAYOUT ISSUES
- **Everything is very spread apart** - the garage doesn't feel alive or cohesive
- **Doesn't flow** - objects feel isolated, not like a real space
- When adding new objects, consider clustering them with related items
- Think about sight lines - what does player see from different positions?
- Add ambient animations to make space feel alive

## DEBUG TOOLS AVAILABLE
- **Use `http://localhost:8000?dev=true`** - skips loading screen, starts in top-down view

- Content data (work history, skills, etc.) lives in js/data/content.js
